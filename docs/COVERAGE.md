Why a rule is not implemented (answer 1A: only rules with an objective, decidable criterion are checked):

| Reason | Rules | Meaning |
|---|---:|---|
| `no-criterion` | 48 | The guideline gives no enforcement criterion: it is a principle or process rule. |
| `incomplete` | 61 | The guideline's own Enforcement section is incomplete ("???"). |
| `not-enforceable` | 21 | The guideline itself says the rule cannot be enforced mechanically. |
| `semantic` | 52 | Needs type, data-flow or whole-program information that a syntax-level analysis does not have (the optional clang-tidy bridge covers part of it). |
| `unreliable` | 36 | The guideline itself calls the proposed check unreliable, or leaves the criterion or its threshold undefined. |
| `superseded` | 3 | Superseded by C++20 (rewritten comparison operators, concepts): enforcing it would contradict C++20. |
| `contradictory` | 2 | Its enforcement hints contradict another rule, so the verdict depends on information the source does not contain. |
| `build` | 6 | Concerns build configuration, tooling or process rather than source code. |

`implemented` means the rule is reported by a built-in check, possibly as one of several rules violated by the same construct. Notes list the interpretation chosen wherever the guideline leaves room.

## Extension rules (`CPP20.*`, answer 5)

Not part of the Core Guidelines: C++20 modernisations. They are always warnings.

| Rule | Severity | What it does |
|---|---|---|
| `CPP20.suppress` | error | The suppression comment itself: it needs a known rule id and a justification (answer 7A). |
| `CPP20.concepts` | warning | std::enable_if / SFINAE replaced by requires clauses (replaces T.48 for C++20). |
| `CPP20.ranges` | warning | std::algorithm(c.begin(), c.end(), ...) replaced by the constrained std::ranges algorithm. |
| `CPP20.spaceship` | warning | operator!= next to operator==, and groups of relational operators, replaced by operator<=>. |
| `CPP20.source_location` | warning | __FILE__ / __LINE__ / __func__ replaced by std::source_location. |
| `CPP20.nodiscard` | warning | Const accessors (and pure free functions in headers) marked [[nodiscard]]. |
| `CPP20.constinit` | warning | Constant-initialised mutable globals declared constinit. |
| `CPP20.bit_cast` | warning | memcpy / reinterpret_cast type punning replaced by std::bit_cast. |
| `CPP20.erase_if` | warning | The erase-remove idiom replaced by std::erase / std::erase_if. |
| `CPP20.contains` | warning | find() != end() replaced by contains(); find(x) == 0 replaced by starts_with(). |
| `CPP20.type_traits` | warning | Trait<T>::value and ::type replaced by the _v / _t variable and alias templates. |
| `CPP20.removed` | warning | Facilities removed or deprecated by C++17/20 (auto_ptr, random_shuffle, bind1st, result_of, register, ...). |
| `CPP20.gsl_to_std` | warning | GSL entities that have a standard equivalent (gsl::span, joining_thread, byte, index, narrow_cast). |
| `CPP20.string_view` | warning | Read-only const std::string& parameters replaced by std::string_view (only when every use is string_view-compatible). |
| `CPP20.numbers` | warning | M_PI and friends replaced by std::numbers. |
| `CPP20.modules` | warning | Opt-in (cpp20Guidelines.modules.enforce): #include of standard headers replaced by import. |
